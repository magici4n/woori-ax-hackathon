# 첨부 프론트 화면 반영 결과

참고 자료: 사용자가 제공한 8쪽짜리 화면 PDF (`Untitled (1).pdf`). 디자인과 사용자 흐름을 참고했으며, PDF 안의 예시 수치와 종목은 실제 앱 데이터로 간주하지 않았습니다.

## 이번에 반영한 화면

| 참고 화면 | 현재 구현 |
|---|---|
| 1. 보유 자산과 시작 버튼 | 시연 계좌의 실제 API 응답으로 평가액·예상 세금·종목별 수량과 손익 표시 |
| 2~3. 내 계좌 분석 | `/api/simulation`의 Java 계산이 진행되는 상태와 완료 결과 표시. 임의의 진행률은 사용하지 않음 |
| 4. 기업 자료 탐색 | 보유 종목 검색·자료 종류 필터·기업 발표 요약·원문 링크·대화 진입 |
| 5. AI 상담 모달 | 기존 챗봇 API, 빠른 질문, 대화 기록, 보유 요약, 조건 미리보기, 직접 조건 수정 연결 |
| 6~7. 시나리오 선택 | 매도 수량·예상 세금·수수료·실현손익·AI 검색 출처가 포함된 세 카드 비교와 선택 |
| 8. 선택한 시나리오 보고서 | 세금 전후 비교·종목별 가상 매도 수량·주의사항·출처·브라우저 PDF 인쇄 |

## 추가 작업이 있어야 하는 기능

| PDF의 표현 또는 기능 | 현재 빠진 이유 | 필요한 작업 |
|---|---|---|
| 실시간 계좌·현재가·매매 이력 | 현재 `/api/portfolio`는 시연 자산 | 증권사 인증·계좌/시세/거래 연동, 개인정보 보호 및 오류 처리 |
| 예정 실적발표·배당일 달력 | 현재 `/api/research`는 확인한 과거 발표 자료이며 실시간 일정 API가 없음 | 일정 데이터 공급원과 조회 API, 공식/추정 여부·시각·시간대·출처 관리 |
| 애널리스트 매수 비율·목표가·실시간 PER | 현재 근거 데이터에 없음 | 별도 라이선스/데이터 API, 발표일·기준일·계산 기준 표시 |
| 투자 목적을 별도 구조화 조건으로 적용 | 현재는 필요 현금과 보유 계획 개월 수를 지원하지만 자유로운 투자 목적 분류는 없음 | 목적별 입력 정의와 검증, 결과 표시 추가 |
| 특정 날짜의 매도 시기·연말 일정 제안 | 거래일, 결제일, 실적 일정과 과세 귀속 검증이 없음 | 시장 캘린더·증권사 결제 규칙·세무 검증을 포함한 일정 엔진 |
| 매도 주문 실행 및 주문 후 리포트 | 주문 API가 없고 시뮬레이션만 수행 | 인증된 거래 연동과 주문 전 확인·취소·체결 처리. 별도 검토 필요 |
| 서버에서 다운로드되는 정식 PDF 파일 | 현재는 브라우저 인쇄 메뉴의 PDF 저장 | 파일 생성 API 또는 클라이언트 PDF 렌더러, 출력 서식·이력 관리 |

기업 자료 화면에서 **최신 자료 조사 시작**을 누르면 `/api/research/live`가 실제 웹 검색을 수행합니다. 출처가 붙은 조사 결과는 서버에서 30분간 재사용하며, 이후 챗봇의 문맥과 시나리오 생성에 전달합니다. 시나리오에는 종목별 매도·보유 이유와 필요 현금 충족 여부를 표시합니다. API 실패 시 Java 기본 계산을 표시하고, 이때 보유 계획은 전략에 반영되지 않았다고 명시합니다. 일정 달력과 배당일은 아직 없으며, 확인하지 못한 미래 일정을 채워 넣지 않습니다. PDF의 Microsoft·Alphabet 종목과 예시 금액은 현재 시연 자산의 Tesla·Apple·NVIDIA·Amazon 및 실제 계산값으로 대체했습니다.
